# lucklyrics-platform

Экземпляр white-label платформы многоканальных продаж: витрина, кабинет продавца,
AI-помощник, синхронизация с маркетплейсом. Код общий для всех продавцов, данные
конкретного — только в `config/brand.json`.

## Команды

```bash
npm test            # 35 проверок, встроенный раннер Node, зависимостей нет
npm start           # сервер на :3000, дальше /api/health
bash web/build.sh   # сборка витрины: подстановка адреса API
```

Node 24 (`.nvmrc`). Тесты гоняются на каждый коммит через CI.

## Структура

```
config/brand.json          данные продавца — единственное место
config/brand.<slug>.json   конфиги для предпросмотра (?preview=<slug>)
api/lib/schema.js          проверка конфигурации при старте
api/lib/config.js          единственная точка чтения конфигурации
api/lib/brand.js           палитра, типографика, логотип, подпись платформы
api/lib/stock.js           единственная точка чтения остатка
api/lib/payments/          адаптеры: интерфейс из четырёх операций
api/lib/marketplace/       клиент площадки, режим сухого прогона
api/server.js              живость, тема, публичный конфиг, журнал намерений
web/                       статика витрины, ассеты экземпляра
tests/unit/                проверки и инварианты
```

## Правила проекта

1. **Одна точка чтения.** Параметр читается в одном месте, дальше по коду идёт
   результат, а не условие. Проверка: «покажи все места, где читается это значение».
   Больше двух — параметр спроектирован неверно, нужен резолвер.
2. **Бренда нет в коде.** Название и домен продавца не встречаются в исходниках.
   Ловится тестом `no-brand-in-code.test.js` — он уже поймал одну утечку.
3. **Ключи только в окружении.** В браузер не попадают никогда. Модель и площадка
   вызываются сервером, не витриной.
4. **Адаптер полон.** Любой платёжный адаптер реализует все четыре операции,
   включая возврат и статус. Заглушка — тоже.
5. **Остаток честен.** Списание уменьшает ровно на количество, отрицательным не
   становится, сумма продаж по каналам не превышает физический остаток.
6. **Тесты в том же коммите, что и код.** Вынесенные «на потом» не пишутся никогда.
7. **Без ключей — только сухой режим.** Клиент площадки физически не может уйти
   в бой без `MARKETPLACE_CLIENT_ID` и `MARKETPLACE_API_KEY`.

## Чего не делать

- Не читать `config/brand*.json` мимо `api/lib/config.js`.
- Не добавлять цвета в конфиг: палитра выводится из одного акцентного в `brand.js`.
- Не подключать произвольные шрифты: типографика выбирается из набора.
- Не переписывать перенесённый код «под свой стиль» — экономия переноса обнулится.
- Не расширять публичный конфиг служебными полями: наружу уходит только тема,
  тексты, юридические ссылки, валюта, ступени скидки, включённые каналы.
- Не ставить зависимости без необходимости: сейчас их ноль, и это ценность.

## Периметр

В работе: витрина, кабинет, AI-помощник, синхронизация с одной площадкой
(оба режима исполнения — свой склад и склад площадки).

Отложено, точки расширения оставлены: вторая площадка, расчёты через внешнюю
систему с эскроу (адаптер-заглушка есть), общий пул остатков вместо буфера,
автовозврат по правилу.

## Состояние

Сделано:
- каркас, конфигурация бренда, развёртывание, конвейер тестов;
- слой брендирования: схема с проверкой при старте, палитра из одного цвета,
  типографика набором, логотип с запасным вариантом, подпись платформы флагом,
  режим предпросмотра чужого конфига;
- платёжный слой: интерфейс из четырёх операций, адаптер провайдера в сухом
  режиме, адаптер внешней системы заглушкой;
- клиент площадки с журналом намерений — работает без боевого ключа.

Следующее: серверная авторизация кабинета — перенос проверенного модуля входа
и защита записи. Сейчас вход в кабинете действующего магазина проверяется
в браузере, это заменяется.

Дальше по плану: каталог и количественный остаток, витрина, платежи, точка
сборки на двадцатый день, затем синхронизация и заказы.

## Открытые решения

- **Наборы** — отдельные позиции со своим остатком или сборка на лету из обычных.
  Входит в схему товара и правило резерва, нужно до начала работы с каталогом.
- **Размер страхового запаса** для схемы буфера.
- **AI-помощник в первой волне** — от этого зависит, проектируется ли корзина
  общей сразу.

Каждое меняет понятия внутри ядра, поэтому решается заранее, хотя делается позже.
