# lucklyrics-platform

White-label платформа многоканальных продаж: витрина, кабинет продавца, AI-помощник, синхронизация
с маркетплейсом. Код общий для всех продавцов, данные конкретного — только в `config/brand.json`.

## Команды

```bash
npm test                                         # 92 проверки, встроенный раннер, зависимостей нет
JWT_SECRET=… npm start                           # сервер на :3000; без секрета не стартует
node api/scripts/add-seller.js <логин> <пароль>  # продавец для кабинета
bash web/build.sh                                # витрина, кабинет, юр. страницы → web/dist
```
Node 24 (`.nvmrc`), CI на каждый коммит.

## Правила проекта

1. **Одна точка чтения.** Параметр читается в одном месте, дальше идёт результат, а не условие.
   Проверка: «покажи все места, где читается значение». Больше двух — нужен резолвер.
2. **Бренда нет в коде.** Название и домен продавца — только в конфиге и в собранной статике;
   шаблоны проверяет `no-brand-in-code.test.js` — он уже поймал одну утечку.
3. **Ключи только в окружении.** В браузер не попадают; модель и площадка вызываются сервером.
4. **Адаптер полон.** Любой адаптер — платёжный, хранилища — реализует все операции; заглушка тоже.
5. **Остаток честен.** Списание уменьшает ровно на количество, отрицательным не становится,
   сумма продаж по каналам не превышает физический остаток.
6. **Сумму считает сервер.** Корзина и заказ идут через одну функцию `catalog.quote`.
7. **Тесты в том же коммите, что и код.** Вынесенные «на потом» не пишутся никогда.
8. **Без ключей — только сухой режим.** Клиент площадки физически не может уйти в бой
   без `MARKETPLACE_CLIENT_ID` и `MARKETPLACE_API_KEY`.
9. **Кто сделал — только из токена.** Продавец и экземпляр не берутся из тела или адреса
   запроса. Маршрут кабинета — только через `cabinet()`.

## Чего не делать

- Не читать `config/brand*.json` мимо `api/lib/config.js`.
- Не добавлять цвета и шрифты в конфиг: палитра — из одного акцентного в `brand.js`, шрифты — набором.
- Не переписывать перенесённый код «под свой стиль» — экономия переноса обнулится.
- Не расширять публичный конфиг служебными полями: наружу уходит только тема, тексты,
  юридические ссылки, валюта, ступени скидки, включённые каналы.
- Не ставить зависимости без необходимости: их ноль. Вход — `node:crypto`, без bcrypt и jsonwebtoken.
- Не подставлять значение по умолчанию вместо `JWT_SECRET`; не хранить токен в localStorage.
- Не менять остаток мимо `stock.js` и не читать поля остатка у товара; поштучного списания
  не заводить — только `reserveMany`, все строки или ни одной.
- Не менять записанное через `read` + `write` — только `store.update`; `fs` в модулях данных нет.
- Не подставлять 0 вместо негодного значения при импорте — только ошибка строки.
- Не вставлять в юридические страницы чужие формулировки — только заглушки «требует проверки юристом».
- Не вставлять данные покупателя в разметку без `esc()`: имя из заказа попадало в кабинет
  как HTML, а там лежит токен.
- Не коммитить посреди rebase или слияния (маркеры конфликта уже раз ушли в историю):
  перед коммитом `git status` и `git grep -n '^<<<<<<<'`.

## Принятые решения

- **Наборы — сборка на лету.** Можно: своя карточка и заданная цена. Нельзя: свой остаток,
  набор в наборе, буфер у набора. Доступность — минимум по составу из `availableStock` с
  кратностью. Списание — все компоненты или ни одного; отмена возвращает ровно списанное.
- **Страховой запас — 2 по умолчанию.** Число даёт только `bufferFor`: позиция в каталоге →
  `stock.bufferBySku` → `stock.bufferDefault`. Ноль у позиции — значение.
- **Остаток — отдельно от каталога.** Любое изменение — в журнал с причиной и автором. Импорт
  без колонки остатка его не трогает, с колонкой — показывает склад отдельно.
- **Медиа — только внешние адреса** у позиции, своего хранилища файлов нет; нет фото — эмодзи
  или первая буква. **Юридический слой** — три страницы из шаблона, реквизиты из конфигурации.

- Вход, токен, маршруты кабинета, заведение продавца — `docs/auth.md`.
- Новая запись данных, реализация хранилища, где что лежит — `docs/storage.md`.

- Импорт каталога: колонки, предпросмотр, остаток и наборы в файле — `docs/import.md`.
- Витрина, фото, заголовки для мессенджеров, юридические страницы, сборка — `docs/storefront.md`.

## Периметр

В работе: витрина, кабинет, AI-помощник, синхронизация с одной площадкой (оба режима
исполнения — свой склад и склад площадки). Отложено, точки расширения оставлены: вторая
площадка, расчёты через внешнюю систему с эскроу (адаптер-заглушка есть), общий пул остатков
вместо буфера, автовозврат по правилу.
