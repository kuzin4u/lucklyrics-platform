# Вход в кабинет

Читать, когда меняете вход, токен, маршруты кабинета или заводите продавца.

## Устройство

- `api/lib/auth.js` — единственная точка работы с сессией: `register`, `login`,
  `verify`, `requireSeller`, `requireOwner`. `JWT_SECRET` и запись `auth`
  в хранилище больше никто не читает.
- Пароль — scrypt из `node:crypto` со случайной солью, хранится строка
  `scrypt$N$r$p$соль$хеш`. Открытого пароля нет нигде.
- Токен — формат JWT (заголовок.нагрузка.подпись, base64url), подпись HMAC-SHA256,
  срок 12 часов. Нагрузка: `sub` — логин, `inst` — экземпляр, `iat`, `exp`.
  Алгоритм зафиксирован, `alg: none` не принимается. bcrypt и jsonwebtoken не нужны.
- `JWT_SECRET` не задан или короче 32 символов — сервер не стартует, модуль
  отказывает (`NO_SECRET`, `WEAK_SECRET` → 503). Значения по умолчанию нет.
- Неверный пароль и несуществующий логин — один ответ `INVALID_CREDENTIALS`;
  чужой логин проверяется против пустышки, чтобы и время ответа совпадало.

## Маршруты

- `POST /api/auth/login` `{login, password}` → `{token, expiresAt, seller}`.
- `GET /api/auth/me` → `{seller, owner}`.
- `POST /api/auth/password` `{oldPassword, newPassword, confirm}` — смена пароля из кабинета:
  логин из токена, отказы `WRONG_PASSWORD`, `WEAK_PASSWORD`, `PASSWORD_MISMATCH`, `SAME_PASSWORD`
  (400, с текстом). В ответ — новая сессия.
- Кабинет, через `cabinet()` в `server.js`: `GET /api/orders`, `POST /api/orders/status`,
  `POST /api/catalog/import`, `GET /api/stock/log`, `POST /api/stock/adjust`,
  `GET /api/sync/log`, `POST /api/sync/run`, `GET /api/sync/diff`, `POST /api/marketplace/orders`,
  `GET /api/marketplace/journal`.
  Новый маршрут кабинета без `cabinet()` — ошибка.
- Без входа: `GET /api/catalog`, `GET /api/product`, `POST /api/cart/quote`, `POST /api/orders`,
  `GET /api/config`, `GET /api/theme`, `GET /api/health`, `POST /api/auth/login`.
- Отказы: 401 `UNAUTHORIZED` (в `reason`: `NO_TOKEN`, `BAD_TOKEN`, `TOKEN_EXPIRED`),
  403 `FORBIDDEN` — чужой экземпляр, 503 — вход не настроен.

## Принадлежность

`cabinet()` передаёт продавца обработчику пятым аргументом. Операция идёт, только
если его экземпляр из токена совпадает с `instance.id` конфигурации. Идентификатор
продавца и экземпляра из тела или адреса не читается никогда; кто сделал операцию
(статус заказа, правка остатка, импорт) — тоже только из токена.

## Сессии и смена пароля

В токене — отметка `pwd`: когда задан пароль продавца. Запрос кабинета сверяет её
с записью продавца: пароль сменили (из кабинета или `--force`) — все прежние токены
отвечают 401 с `reason: PASSWORD_CHANGED`; продавца нет — `SELLER_GONE`. Поэтому
проверка входа читает запись продавца на каждом запросе кабинета.

## Кабинет в браузере

Токен живёт в памяти страницы, не в localStorage: перезагрузка — новый вход.
Уходит заголовком `Authorization: Bearer`. На 401 — снова форма входа с пояснением,
на 403 — сообщение о чужом экземпляре. Данные покупателя в разметку — только через
`esc()`: иначе имя из заказа исполняется на странице, где лежит токен.

## Продавцы

`node api/scripts/add-seller.js <логин> <пароль> [--force]` — продавец текущего экземпляра.
Логин уже есть — отказ; `--force` перезаписывает пароль (сброс забытого) и обрывает его сессии.
Логин 3–64 символа, пароль от 8. На площадке — через Shell сервиса API; продавец
лежит на постоянном диске и переживает развёртывания (см. `docs/deploy.md`).

## Не сделано

Ограничения числа попыток входа нет — нужно до того, как кабинет станет публичным.
