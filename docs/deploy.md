# Развёртывание

Читать перед первым развёртыванием и когда что-то не поднялось. Площадка — Render,
описание в `render.yaml`: создать Blueprint из репозитория, дальше — по шагам ниже.

## Что поднимается

| Сервис | Что это | Главное |
|---|---|---|
| `platform-api` | Node, план starter | старт `node api/server.js`, живость `GET /api/health`, постоянный диск `/var/data` на 1 ГБ |
| `platform-web` | статика | сборка `bash web/build.sh` из корня репозитория, публикуется `web/dist` |

Диск нужен потому, что вся остальная файловая система стирается при каждом развёртывании:
на нём заказы, продавцы, каталог и остаток. С диском развёртывание не бесшовное —
несколько секунд API недоступен. Диск платный (копейки за гигабайт) — это решение
владельца; без него после каждого развёртывания данные начинаются с нуля.

## Переменные

| Переменная | Сервис | Что задать |
|---|---|---|
| `JWT_SECRET` | api | ничего: Blueprint генерирует сам. Свой — от 32 символов |
| `BRAND_CONFIG_JSON` | api и web | содержимое `config/brand.json` одной строкой, **одинаковое** в обоих |
| `DATA_DIR` | api | уже `/var/data` — путь диска |
| `MARKETPLACE_CLIENT_ID`, `MARKETPLACE_API_KEY` | api | пусто — сухой режим площадки |
| `PAYMENT_SHOP_ID`, `PAYMENT_SECRET_KEY` | api | пусто — сухой режим платежей |
| `MODEL_API_KEY` | api | пусто: AI-помощник ещё не подключён, ключ пока не читается |
| `API_HOST` | web | уже подставлен из `platform-api` |
| `API_URL` | web | пусто; задать адрес API, если у него свой домен |

**Без `JWT_SECRET` API не стартует — это не ошибка, а защита.** В журнале сервиса строка
`Сервер не запущен: JWT_SECRET не задан — вход в кабинет отключён`. Подставлять значение
по умолчанию нельзя: с известным секретом любой подпишет себе вход в кабинет. Render при
неудачном развёртывании оставляет работать прежнюю версию. Так же API не стартует, если
конфиг бренда задан, но негоден: `Сервер не запущен: BRAND_CONFIG_JSON: …`.

## Конфиг бренда

- Локально — файл `config/brand.json` (в git не попадает).
- На площадке — переменная `BRAND_CONFIG_JSON` в **обоих** сервисах: API читает её при
  работе, статика — при сборке (заголовки, Open Graph, тема, реквизиты). Строка из файла:
  `node -e "console.log(JSON.stringify(require('./config/brand.json')))"`.
- Изменили конфиг — обновить переменную в обоих сервисах и пересобрать оба.
- Логотип, фавикон и картинка для мессенджеров — файлы `web/assets/logo.png`,
  `favicon.png`, `preview.png` в репозитории экземпляра.
- Проверка: `GET /api/health` → `configSource: "env:BRAND_CONFIG_JSON"`. Если там
  `brand.example.json` — поднят демонстрационный магазин, а не магазин продавца.

## После первого развёртывания

1. `https://<api>.onrender.com/api/health` отвечает `ok: true`, в `storage` — `file`.
2. Завести продавца: в Render → `platform-api` → Shell
   `node api/scripts/add-seller.js <логин> <пароль>` — пароль от 8 символов. Продавец
   лежит на диске и переживает следующие развёртывания.
3. Для проверок — отдельный продавец, например `smoke-check`, со своим паролем.
4. Прогнать приёмку с рабочей машины:
   ```bash
   SMOKE_LOGIN=smoke-check SMOKE_PASSWORD=… npm run smoke https://<api>.onrender.com -- --web https://<web>.onrender.com
   ```
   Печатает шаги с отметками ✓ ✗ ⚠, код выхода 0 — приёмка пройдена. Создаёт один
   заказ «SMOKE — тестовый заказ» и отменяет его; в кабинете он виден отменённым.
   Предупреждения ⚠ не валят приёмку: пример вместо конфига, заглушки юридических текстов,
   боевой режим платежей (тестовый заказ создаст неоплаченный платёж — он истечёт сам).
5. Пройти `docs/acceptance.md` человеком — первый раз и перед запуском продаж.

После каждого следующего развёртывания — шаг 4.

## Если не поднялось

| Признак | Причина |
|---|---|
| API не стартует, «JWT_SECRET не задан» | секрет удалён — вернуть (от 32 символов); это защита |
| API не стартует, «BRAND_CONFIG_JSON: …» | в переменной не JSON или конфиг не прошёл проверку — текст говорит, какое поле |
| Витрина: «Не удалось загрузить витрину» | статика смотрит не на тот адрес API: задать `API_URL`, пересобрать; `smoke --web` покажет адрес |
| Витрина с названием «Название магазина» | в `platform-web` не задан `BRAND_CONFIG_JSON` |
| Заказы и продавцы пропали после развёртывания | нет диска или `DATA_DIR` не `/var/data` |
| Вход в кабинет → «чужой экземпляр» | продавец заведён под другой `instance.id` |
| Приёмка: «остаток: было N, стало M» не сходится | между шагами прошёл настоящий заказ — повторить |
